Key decisions

Decision 01

One conversational agent with bounded workflows

Chose

Single agent handles both use cases with a shared conversation model and context.

Trade-off

Requires careful intent routing. Specialist agents would be simpler per case.

Why

Simpler conversation state and a consistent customer experience. Introduce specialist agents only when complexity or evaluation supports the split.

Decision 02

Progressive authority based on customer context

Chose

Order tracking requires order number and matching email. Refunds require eligibility and explicit customer confirmation.

Trade-off

More steps in the refund flow versus a flat permission model.

Why

Risk is proportional to action. Read-only tracking carries lower stakes than executing a financial transaction.

Decision 03

Policy and action controls enforced in tools

Chose

Code validates business rules and executes approved actions. The model handles language and selects the next step.

Trade-off

Business logic must be explicitly coded — the model cannot improvise edge cases.

Why

One versioned rule with automated tests is safer than a prompt instruction. Structured handoff output is a candidate regression test, not just a UX affordance.

Pathway to production — three phases, each a gate for the next

Phase 1 — Foundation

Before first real user

Entry criterion No real traffic until all of this is in place.
Customer auth & session-scoped permissions — the agent must receive a verified identity, not validate it
Live integrations with idempotent writes, transaction reconciliation, and durable audit records
PII detection and data handling compliance before any conversation is logged
Seed eval set from day-zero conversations — even 50 labelled examples unblock everything in Phase 2
→unlocks
Phase 2 — Quality gate

Before real volume

Entry criterion Eval pass rate meets defined threshold on golden set.
Deterministic checks: did the right tool fire with the right arguments?
LLM-as-judge quality scoring for tone, accuracy, and resolution completeness
Shadow testing — run candidate versions against live traffic before serving responses
Prompt and model version control with automated regression detection on every change
Canary rollout with automatic rollback on quality drop
→unlocks
Phase 3 — Sustain at scale

Operating autonomously

Entry criterion P95 latency and quality metrics within agreed SLA.
Distributed tracing: request → LLM call → tool call → response, with cost per conversation
Tool resilience: timeouts, bounded retries, circuit breakers, durable session state
Confidence thresholds for auto-escalation before quality degrades, not after
HITL correction loop: reviewed agent mistakes become the next eval batch — the system improves itself
Continuous improvement loop
Production conversations → HITL review → Correction dataset → Eval regression → Prompt / model update → Shadow test → Canary rollout → Production
